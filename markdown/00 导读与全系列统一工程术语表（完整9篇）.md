## 二、全系列统一工程术语对照表

 为避免技术译文中常见的术语歧义，全辑 9 篇文章统一采用以下中文译法（文中首次出现或关键处同步保留英文原词）：

| 英文原词 | 本辑统一译法 | 工程语境说明 |
| --- | --- | --- |
| `Agent / Agentic systems` | 智能体 / 智能体系统 | 严格区分“预定义路径的工作流”与“模型自主决策循环的智能体” |
| `Workflow` | 工作流 | 由确定性代码预先编排 LLM 与工具调用顺序的系统 |
| `Harness / Meta-harness` | 执行框架（Harness）/ 元框架 | 包裹在模型外围、负责调用循环、路由工具、管理状态与环境的运行时脚手架 |
| `Context rot` | 上下文腐败 | 随着上下文窗口 Token 增加，模型精准召回与遵循指令能力持续下降的现象 |
| `Context anxiety` | 上下文焦虑 | 长程任务中模型感知窗口逼近上限时，急于草草收尾或提前宣布完成的倾向 |
| `Attention budget` | 注意力预算 | Transformer 架构下有限的注意力分配容量，每新增一个 Token 都会消耗预算 |
| `Progressive disclosure` | 渐进式披露 | 仅在初始加载轻量目录或元数据，运行时按需逐层展开详细指令与工具定义 |
| `Compaction / Context reset` | 上下文压缩 / 上下文重置 | 压缩指在原会话提炼摘要继续；重置指清空窗口、借助外部结构化产物交接给全新会话 |
| `Ground truth` | 客观真值 / 环境真实反馈 | 工具执行输出、测试通过状态、数据库真实变更等来自外部环境的客观事实 |
| `ACI / Poka-yoke` | 智能体-计算机界面 / 防呆设计 | 像打磨人类 UI（HCI）一样打磨给模型用的工具定义，从接口与参数上防止犯错 |
| `Pets vs. cattle` | “宠物 vs. 牲畜” | 基础设施运维隐喻：不可替代需悉心照料的实例 vs 可随时销毁重建的无状态实例 |
| `Task / Trial` | 测试任务 / 单次运行 | Eval 中的单个明确测试目标（Task）及其一次独立执行尝试（Trial） |
| `Transcript vs. Outcome` | 执行轨迹 vs. 最终状态结果 | 轨迹是全过程对话与工具调用日志；结果是环境（数据库/文件系统）中的真实终态 |
| `Grader` | 评分器 | 判定单次运行是否通过的机制，分为代码评分器、模型评分器与人工评分器三类 |
| `pass@k / pass^k` | `pass@k` / `pass^k` | `k` 次独立尝试中“至少成功一次”的概率 vs “全部连续成功”的概率 |
| `Planner / Generator / Evaluator` | 规划 / 生成 / 评估智能体 | 受 GAN 启发的三权分立长程架构，通过独立评审打破单模型自我放水的盲区 |
| `Salience` | 显著性 / 留存价值 | 判断一条交互经验是否值得跨会话持久化，而非事后重新推导的能力 |
| `Dreaming / Sleep-time compute` | “做梦”离线巩固 / 休眠期计算 | 智能体空闲时在后台回读历史轨迹与笔记，执行纠错、去重、提拔与结构化归纳的过程 |
