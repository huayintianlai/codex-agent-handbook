Equipping agents for the real world with Agent Skills

我们已将 Agent Skills 作为开放标准正式发布，支持跨平台移植复用。[了解更多（agentskills.io）↗](https://agentskills.io/)

 随着模型能力的提升，我们如今已经能够构建与完整计算环境交互的通用智能体。例如，Claude Code 借助本地代码执行和文件系统，已经能够跨领域完成高度复杂的任务。但随着通用智能体越来越强，我们需要一种**更易组合、可扩展且可移植**的方式，为它们注入特定领域的专业能力。

 由此，我们创造了 **Agent Skills（智能体技能）**：由指令、脚本和参考资源有序组成的文件夹，智能体可以动态发现并按需加载，从而在特定任务上发挥专业水准。Skills 通过将你的专业经验打包成可供 Claude 使用的可组合资源来扩展其能力，把通用智能体转化为贴合你业务需求的专职智能体。

 为智能体编写一个 Skill，就像为刚入职的新员工整理一份《入职操作指南》。人们不再需要为每个细分场景碎片化地从零定制专属智能体，而是通过沉淀和共享**程序性知识（procedural knowledge）**，用可组合的能力模块按需武装智能体。在本文中，我们将阐明什么是 Skills、它如何运作，并分享编写自有技能的最佳实践。

> **【图表说明】** 官方原图（中文化）：Skill 是一个包含 `SKILL.md` 文件的目录，内含按结构组织的指令、脚本与资源文件夹，为智能体赋予额外能力。



## 一、Skill 的解剖结构（The anatomy of a skill）

 为了看清 Skills 如何实际工作，让我们剖析一个真实案例——支撑 Claude 近期推出的文档编辑能力的 **PDF 技能**。Claude 本身已经很擅长理解 PDF 内容，但直接操作 PDF（例如填写 PDF 表单）的能力有限，而这个 PDF Skill 正是为 Claude 赋予了这类新本领。

 在最简形态下，一个 Skill 就是一个包含 **`SKILL.md`** 文件的目录。该文件必须以 YAML 前置元数据（frontmatter）开头，其中包含两项必填字段：`name`（名称）和 `description`（描述）。在启动阶段，智能体会把所有已安装技能的 `name` 和 `description` 预加载进系统提示词。

 这组元数据正是**渐进式披露（progressive disclosure）的第一层**：它提供的信息刚好足以让 Claude 判断何时应当启用哪一项技能，而无需把所有技能全文一股脑塞进上下文。`SKILL.md` 的正文则是**第二层细节**——只有当 Claude 判断该技能与当前任务相关时，才会把完整的 `SKILL.md` 读入上下文。

> **【图表说明】** 官方原图（中文化）：`SKILL.md` 文件必须以包含名称与描述的 YAML Frontmatter 开头，并在启动时预加载至系统提示词中。



 随着技能变得越来越复杂，里面可能包含过多无法全塞进单个 `SKILL.md` 的上下文，或者某些说明只在特定子场景下才用得上。此时，技能作者可以在目录中打包额外的参考文件，并在 `SKILL.md` 中按文件名引用它们——这些链接文件构成**第三层（及更深层）细节**，Claude 仅在真正需要时才定位并按需读取。

 在如下所示的 PDF 技能示例中，`SKILL.md` 引用了两个随核心文件一并打包的附加文件：`reference.md` 和 `forms.md`。通过把表单填写指南独立拆进 `forms.md`，作者让核心 `SKILL.md` 保持轻巧精干，同时放心地把 `forms.md` 留到确实需要填表时再由 Claude 按需加载。

> **【图表说明】** 官方原图（中文化）：你可以在 Skill 中通过附加文件（如 `reference.md`、`forms.md`）打包更多上下文，再由 Claude 根据系统提示词按需触发读取。



 **渐进式披露是让 Agent Skills 兼具灵活性与可扩展性的核心设计原则。**就像一本编排精良的技术手册——先看总目录，再翻到对应章节，最后按需查阅详尽附录——Skills 让 Claude 始终只加载当下所需的信息：

> **【图表说明】** 官方原图（中文化）：Agent Skills 的三层渐进式上下文披露机制。



 对于拥有文件系统和代码执行工具的智能体而言，处理特定任务时无需将整个技能读入上下文窗口。这意味着**单个 Skill 目录内可捆绑的上下文容量，在实际上几乎没有上限**。

### Skills 与上下文窗口的交互过程（Skills and the context window）

下图展示了当用户的消息触发某项技能时，上下文窗口如何动态变化：

> **【图表说明】** 官方原图（中文化）：Skills 通过系统提示词在上下文窗口中被按需触发并加载。



图示操作流程如下：

1. 初始状态下，上下文窗口里包含核心系统提示词、所有已安装技能的轻量元数据（名称与描述），以及用户的首条消息；
1. Claude 通过调用 Bash 工具读取 `pdf/SKILL.md` 的内容来触发 PDF 技能；
1. Claude 进一步选择读取随技能一并打包的 `forms.md` 文件；
1. 最终，在加载完 PDF 技能的相关指南后，Claude 顺利推进并完成用户的任务。


### Skills 与代码执行（Skills and code execution）

 Skills 内部还可以打包**可执行代码**，供 Claude 自行决定当作工具运行。

 大语言模型擅长许多任务，但某些操作更适合交给传统代码执行——例如通过逐个 Token 生成来给列表排序，其成本远高于直接运行一个排序算法。除了效率考量外，许多应用场景本身就需要只有代码才能提供的确定性可靠性。

 在我们的 PDF 技能示例中，目录里预置了一段用于读取 PDF 并提取所有表单字段的 Python 脚本。Claude 可以直接运行这段脚本，**既不必把脚本源码、也不必把原始 PDF 内容加载进上下文窗口**。而且因为代码行为完全确定，整套流程高度稳定且完全可复现。

> **【图表说明】** 官方原图（中文化）：Skill 还可内置可执行代码（如 `extract_fields.py`），供 Claude 视任务性质自行决定当作工具调用。



## 二、开发与评估 Skills 的实战指南（Developing and evaluating skills）

以下几条实用原则可帮助你高效编写并测试自己的技能：

- **从评估起步（Start with evaluation）**：先让智能体跑一批有代表性的真实任务，观察它在哪里卡壳或缺少上下文，找准具体能力缺口，再针对这些短板增量构建 Skills。
- **为扩展性设计目录结构（Structure for scale）**：当 `SKILL.md` 日渐臃肿难以维护时，及时将其拆分成独立文件并在主文件中引用。如果某些上下文彼此互斥或极少同时用到，把它们拆进不同文件能显著节省 Token。另外，代码既可以当可执行工具，也可以当参考文档——务必写清楚 Claude 应当直接运行脚本，还是先读进上下文做参考。
- **站在模型的视角思考（Think from Claude's perspective）**：在真实场景中持续观察 Claude 是如何使用你的技能的，根据实际表现迭代——留意它是否走偏了路径，或过度依赖某段上下文。**尤其要精心打磨技能的 `name` 和 `description`**，因为 Claude 正是凭这两项元数据来决定当前任务要不要触发该技能。
- **与模型共同迭代（Iterate with Claude）**：与 Claude 协作完成任务的过程中，直接让它把跑通的成功做法和常见踩坑提炼成可复用的上下文和脚本沉淀进 Skill。如果它在使用技能时跑偏了，让它自我复盘究竟哪里出了岔子——这种做法能帮你发现 Claude **真正需要**什么上下文，远比事前凭空猜测精准得多。


### 使用 Skills 时的安全考量（Security considerations when using Skills）

 Skills 通过指令和可执行代码赋予 Claude 强大新能力，但这也意味着**恶意 Skill 可能在运行环境中引入安全漏洞，或诱导 Claude 窃取数据、执行非预期操作**。

 我们建议**仅从受信任的来源安装 Skills**。如果必须使用来自非完全可信来源的技能，务必在启用前彻底审计：先逐一阅读目录内打包的所有文件内容，弄清它到底会做什么，重点核查代码依赖项以及附带的图片、脚本等资源；同时警惕技能中任何诱导 Claude 连接潜在不可信外部网络来源的指令或代码。

## 三、Skills 的未来（The future of Skills）

 目前，Agent Skills 已全面支持 Claude.ai、Claude Code、Claude Agent SDK 及 Claude 开发者平台。

 在接下来的几周里，我们将持续推出新特性，覆盖 Skills 创建、编辑、发现、共享与使用的全生命周期。我们尤其期待看到 Skills 帮助组织与个人与 Claude 高效共享自身的上下文与工作流。我们还将探索 **Skills 如何与模型上下文协议（MCP）服务器形成互补**——通过教会智能体如何完成涉及外部工具与软件的更复杂工作流。

 放眼更远的未来，我们希望让智能体能够自主创建、编辑并评估 Skills，将自身在实践中形成的有效行为模式固化为可复用的能力资产。

 Skills 是一个简洁的概念，也配有同样简洁的格式。正是这种简洁性，让组织、开发者和终端用户都能更轻松地构建定制化智能体并赋予它们新能力。

 我们非常期待看到大家用 Skills 打造出怎样的作品。欢迎查阅我们的 [Skills 官方文档](https://docs.claude.com/en/docs/agents-and-tools/agent-skills/overview) 与 [Cookbook 示例集](https://github.com/anthropics/claude-cookbooks/tree/main/skills) 立即上手体验。

## 💡 译者附注（非原文）：如何把本篇用到 AI 客服与全自动运营 Agent



- **用“MCP 管连接 + Skills 管 SOP”解耦客服与运营知识**：把订单/退款/工单接口沉淀在业务 MCP 里，而把“大促价保规则”“VIP 客诉升级话术”“异常渠道止损 SOP”分别打包成独立 Skill 文件夹；GPT-6.2 启动时只看几十字节的 `name + description`，触发到对应场景才按需读详细手册。
- **把确定性核算下沉成 Skill 里的 Python/TS 脚本**：例如价保差价计算、运费险分摊、多阶梯满减反算，绝不让大模型心算——直接随 Skill 附带一个校验脚本，由智能体传入参数运行并拿回 100% 精确数字。
- **用 Codex 把人工客服踩坑自动沉淀成新 Skill**：每周挑选 5 个 AI 处理翻车但人工救回的工单，把对话记录丢给 Codex，让它自动更新对应 Skill 目录下的边界案例文件或补充判断清单，形成持续复利。
- **严守 Skill 上线安全审计**：任何运营技能合并进生产仓库前，走 Codex 只读审计检查是否存在外发数据、越权调写接口或硬编码密钥风险。
